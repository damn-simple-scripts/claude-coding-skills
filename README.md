# why this exist
I insist on reviewing code AI is generating before using it. I noticed that AI is generating a lot of "hacky" code or follow patterns that are hard to review as a human. I also notice that a lot of the code AI generated tends to break apart when you extend on it or the project outgrows its intended purpose. I also noticed that Claude was not consistent with testing of code.

These skills should fix this behaviour. These skills are intended as addition to other skills like ponytail. 

A lot of these rules are my personal preference and may not apply to you. This skill will increase development time due to the tests that are generated. This skill will also increase the amount of code generated - but it should be more easy to review and reuse.

The test-script provided with the python skill was created using Claude Code - it is not handcrafted - I tried my best to test it for false positives - it also does not cover all the rules.

Since the ruleset is a lot of interpretation I got the best results with a dedicated agent that gates the process using this skill.

# notes regarding each skill
## python-style
I ran into multiple issues where AI tried to do something "clever" or "hacky". Probably because too much leetcode is in the trainingsdata. The skill emphasis is to produce clean, readable code that is easy to review and reuse. This is done by rules mostly imposing YAGNI, DRY, we read left to right, making it obvious and preventing typical mistakes (like aliases). We also try to impose the view of the "general programmer" - not a python expert. We also try to add meaings (e.g. is this if a guard clause or are we picking between 2 options).
This skill has little security emphasis. We do not intend to expose to the web (e.g. using django) - for that we have other skills (rust-style or web-style).

## rust-style
This skill focuses on a style that should help to review the code generated by the model by making it easy to read and understand. 
This skill should also help to create secure sidecars for other applications (e.g. secure process management, better to audit by exposing SBOMs, reduced attack surface in container images by creating from scratch). We also seperate the usecases "rust for fast applications" and "rust for secure sidecars".

## web-style
This skill helps to produce modern secure web applications. We do this by following methods such as CSP, security in depth and making it easy to verify. We also try to mitigate exposure for DoS and injection attacks. We also try to use modern web standards (e.g. preloads, subresource integrity, defer/async loading, image source sets).
Javascript should become more predictable.
HTML should become more predictable and obey CSP.
PHP should become more secure.

PHP explicitly follows YAGI by using vanilla PHP instead of frameworks, we also violate DRY so endpoints become more easy to verify and making security obvious to the reviewer. This skill does not include methodology for MVC (model view controller) or other methodologies - we aim for simple small less complex endpoints.
